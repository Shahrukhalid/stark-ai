# STARK AI 2.3.0

## Local AI with Ollama, and a tested Docker setup

This release finishes the work left on two older branches: `feature/nexonic-local-provider`, whose PR #35 was closed unmerged, and `test/docker-compose`.

### Run the assistants on your own computer
- **Ollama provider.** Set STARK to use a model running in your own Ollama, with `STARK_DEFAULT_PROVIDER=ollama`, `STARK_OLLAMA_URL` and `STARK_OLLAMA_MODEL`, or choose **Ollama** in the desktop first-run setup. No cloud key is needed.
- **Safe local requests.** Requests go only to a literal loopback address. Proxies and redirects are off, request and response sizes are bounded, and cloud model names and remote-model metadata are refused.
- **Models screen.** Lists your installed local models and lets you choose a model per assistant. Downloads need your licence confirmation and show real byte progress. They have a size budget and a time limit, can be cancelled, and are reported as done only after the model is inspected.
- **Optional cloud fallback, per assistant.** It is off by default. When you turn it on, a free OpenRouter model is used only if local inference fails. Stopping a task, or the emergency stop, prevents the fallback.
- **Real inference test.** `scripts/test_local_ollama.py` runs a real local model end to end. CI runs it on Windows with the pinned official Ollama 0.40.15 (SHA-256 checked).

### Self-hosting
- **New Docker workflow.** Builds the images, starts STARK with the production override and checks that both services answer. It then stops and starts again to confirm the data survives.

See docs/NEXONIC_LOCAL_AI.md for details and the acceptance record.
